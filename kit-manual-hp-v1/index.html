採用HP 制作キット（spinova-hp-kit）v1.0 試用版

採用HP 制作キットの使い方 （v1.0 試用版）

採用HP（TOP と下層ページ）を、毎回同じ土台と同じ検査で作るためのキットの手引きです。AI やターミナル（文字でパソコンに指示を出す画面）に慣れていなくても進められるよう、「あなたがすること」と「AI がすること」を分けて書いています。採用LP は別のキット（spinova-lp-kit）です。

このキットを使う前に（必ず守ってください）
  1. このキットとマニュアルは、SPINOVA の制作のためだけに使ってください。ほかの仕事や個人の制作には使わず、人にも渡さないでください。
  2. キットの中身（手順書・道具・土台）は、自分で書き換えないでください。AI に頼んでも書き換えません。直したい所は、責任者へ伝えてください。
  3. キットで作ったサイトには、このキットで作られたことが分かる目印（版と印）が入ります。
  4. ヒアリングシートにある認証情報（FTP・WordPress の ID とパスワード）は、AI に読ませない・貼らないでください。

1このページについて

結論：キットをパソコン（Mac・Windows）に置き、AI のアプリでキットのフォルダを開いて案件を渡すと、AI が採用HP を作ります。最初に見せるのは TOP だけ。TOP の OK が出てから下層ページを作ります。あなたの仕事は「選ぶ・見て直しを伝える・OK を出す・送る」です。

できること

  • ヒアリングシートから、TOP と下層（私たちについて・事業内容・会社概要・お問い合わせ）を作る
  • リンク切れ・はみ出し・最小の文字・メニュー・読みやすさ・改行などを道具で検査する
  • 合格し、承認がそろったものだけを公開する（版ごとの URL）

作らないもの

  • 採用ページ（採用情報は採用LP へのリンクにします）
  • WordPress への移行の手順（HP 版はまだありません。10章）

2LP キットとの違い

結論：進め方の大筋（シートを読む → 要件を整理 → 参考サイトを分析 → 最初の画面を見せる → 検査 → 承認 → 公開 → 修正）と、あなたの役割・守ることは、採用LP キットと同じです。違うのは作るものの形（1ページのスワイプ型か、TOP と下層の複数ページか）と、それに合わせた検査と道具の範囲です。

4必要なもの

パソコン

  • macOS か Windows（Git Bash）
  • Google Chrome
  • Node.js 22 以上
  • Python 3 と Pillow

AI のアプリ

  • Claude のデスクトップアプリ（Claude Code）など、フォルダを開いて作業できる AI
  • キットのフォルダにある手順書（AGENTS.md＝CLAUDE.md）を AI が読みます

公開するとき

  • Cloudflare のアカウント（Cloudflare Pages。wrangler にログイン）
  • 確認用の GitHub Pages：git と、GitHub の操作に使う道具（gh）へのログイン。リポジトリと Pages は、公開の道具が自動で作ります

そろっているかは、5章の「初回の準備」で AI が tools/setup_check.sh を使って確かめます（入れる操作は、説明してから）。

5初回だけの準備

  1. ZIP を置く場所を決めて、解凍する

    例：「HP制作」フォルダを作り、その中に解凍します。フォルダの名前（spinova-hp-kit_v1.0）は変えないでください。

  2. AI のアプリで、キットのフォルダを開く（ここまでがあなた）

    解凍してできた spinova-hp-kit_v1.0 フォルダを選びます（その中の projects などではなく、いちばん外のフォルダ）。

  3. AI に「初回の準備をして」と頼む（あとは AI がやる）

    初回の準備をしてください。
1. AGENTS.md を読む
2. tools/setup_check.sh で点検し、足りないものがあれば、入れ方を説明してから進める
3. tools/version.sh でキットの版を教える

    表の「状態」がすべて OK（⚠ は説明を読んで判断）になれば準備は終わりです。

6案件ごとの流れ：TOP の初稿を出すまで

結論：あなたがするのは「案件を渡す」「質問に答える」「TOP を見て直してほしい所を伝える」「OK を出す」「先方へ送る」です。作る・調べる・検査する・公開するのは AI です。確認はそのつど来るので、制作中は返事ができるようにしてください。

案件ごとに、新しいチャットを作ってください。1つのチャットで複数の案件を進めると、AI が案件どうしを取り違えます。修正もその案件のチャットで続けます。

最初の一言（コピーして AI に送る）

新しい HP の案件を始めてください。
担当案件：〔担当案件の URL か、ヒアリングシートの場所を書く〕
進め方の選択・公開・クライアントへの送信は、私が決めます。
1案件を渡す
あなた
  • 上の「最初の一言」を送る
  • ヒアリングシートは Google のサインインが要ります。AI の内蔵ブラウザで、初回だけあなたがサインインします（AI はパスワードを入れません）
AI
  • 案件のフォルダを作る（projects/ の中）
  • 作業中は、シート・参考サイト・手元の確認・確認用の GitHub の4つをブラウザに開いておく（あなたがいつでも進み具合を見られるように）
2進め方を選ぶ・食い違いに答える
あなた
  • 選択カードで選ぶ：初稿の範囲（標準は TOP だけ）・案の数・写真の方針（先方の写真／フリー素材／AI 生成／イラスト）
  • AI 生成の写真を使うときは、先に先方の了承を取る
  • シートの食い違い（住所・郵便番号・社名の書き方・色など）をまとめて1回聞かれるので、答える
AI
  • シートを全部読み、確定・解釈・未定に分けて 要件整理.md に書く
  • シートに無い事実（電話・郵便番号など）は作らない。仮のまま残すか、項目ごと外すかを聞く
  • 色の名前しか無いときは、近い色を仮に置いて、あなたに確かめる
3参考サイトを調べる
あなた
  • AI が開けないリンク（Canva・Drive など）は、開いて要点を伝える
  • 参考サイトの指定が無い案件は、AI が方針を報告してくるので、責任者に確かめる
AI
  • 参考サイトを PC とスマホで見て、「らしさ」と数値を DNA.md に書く（持ち込むのは数値と型だけ。画像やコードは持ち込まない）
  • 先方の「参考にしてほしい点」は、実際に操作して確かめる
4TOP を作って、見る
あなた
  • 届いた画像（ページ全体を PC・スマホ各1枚）を見て、直してほしい所をまとめて伝える
  • OGP（URL を貼ったときに出る画像）とファビコンを見て OK を出す
AI
  • TOP を作り、写真を1枚ずつ確かめ（写真チェック.md）、ロゴを差し替える
  • 撮った画像を自分で見てから渡す。直しの途中は、直した所を撮って見せるだけ（全部の検査は公開の前に1回）
  • 社内で見る確認用の URL（GitHub Pages）は、了承なしで AI が出す
5TOP だけの初稿を出す
あなた
  • 責任者の OK をもらい、AI に「OK、公開に進んで」と伝える
  • 届いた URL を自分の目で見て、共有文面の下書きを直して先方へ送る（送るのはあなた）
AI
  • 公開の門（検査）→ 承認の記録 → 公開 → 公開した中身の照合（8章）
  • 下層は中身を作る前の仮ページのまま出す（仮ページは時間のかかる検査を省く）。共有文面に「今回は TOP のみ」「仮の所」を書く

7下層ページを作る（TOP の OK のあと）

結論：先方から TOP の方向に OK が出たら、「下層を作って」と伝えます。基本は4ページ（私たちについて・事業内容・会社概要・お問い合わせ）で、シートの構成に合わせて増やせます。

  • ヘッダー・フッター・メニューは TOP が元で、道具が全ページへ写します。メニューとフッターには「トップ」が入ります。
  • 同じ役割の見出し・ボタン・表は、ページの間でそろえます。同じ写真・同じ構図は使い回しません。
  • お問い合わせフォームは見た目までです。送信の仕組みは WordPress への移行で入ります（10章）。
  • 確定の文が無い所は仮の文にし、提出のときに「仮の所」として伝えます。

8提出前のチェックと公開

結論：公開は道具（tools/publish.sh）だけで行います。検査に合格し、その版の承認の記録があるときだけ公開されます。止まったら、止めた理由を直します。

確かめる段は3つ（A・B・C）

A　道具が判定

  • リンク切れ・はみ出し・最小の文字 13px・メニューの開閉・電話と〒の折れ
  • 文字の読みやすさ（コントラスト）・絵の見切れ・文節の途中の改行
  • ✕ が0になるまで AI が直す

B　AI が見て直し、責任者が画像で承認

  • 改行・余白の段階・写真・ページ間のそろい・参考サイトらしさ
  • 全ページを PC・スマホ各1枚の画像で見る

C　責任者だけが判断

  • 見た目の質・写真の選び方
  • iPhone の実機で触ったか（見ていなければ「未確認」）
  • 提出・公開してよいか

公開の流れ

  1. 確認用で先に見る（社内）

    確認用の GitHub Pages に出して社内で見ます。了承は要らず、リポジトリや Pages が無ければ道具が作ります。いきなり先方用を出しません。

  2. 責任者の OK を、版ごとに記録する

    責任者がチャットで「OK、公開に進んで」と伝えたときだけ、AI が承認の行を書きます（版ごとに1行。前の版の OK は使い回しません）。

  3. 公開する

    版ごとの URL（v1・v2 …）で公開されます。前の版の URL は上書きされません。公開のあと、道具が公開された全ファイルを手元と照合します。

  4. 共有文面を送る

    AI が下書きを作ります。書くのは URL と「仮の所・通常と変えた点」だけ。送るのはあなたです。

検査の時間と、急ぎの公開

  • 時間の目安（試しの5ページ・手元での計測）：初回は全ページで約3分。2回目からは、前の公開から変わったページだけを時間のかかる検査（文字の読みやすさ・絵の見切れ・改行）にかけ、変わったページが無ければ約1分半です。どのページを見て、どのページを見ていないかは、出力に出ます。
  • 急ぎの公開：責任者が「検査とばせ」「すぐ出して」と言った版だけ、時間のかかる検査を省いて出します（ほかの検査・承認・公開後の照合はいつも通り）。省いた分は、次の版を出すときにまとめて検査します。本番の URL には使えません。手で公開することはしません。

9クライアントから修正が来たら

結論：修正の指示（Slack のスレッドの URL など）を、その案件のチャットに貼るだけです。AI はまとめて直し、直した所を見せ、版を上げて公開し、返信文の下書きと比較画像を渡します。

修正が来ました。修正時.md の手順で進めてください。
修正の指示：〔Slack のスレッドの URL か、指示の文を貼る〕
  • 先方へ出した後の直しは、必ず版を上げます（v1 → v2）。前の版の URL は残るので、先方が見比べられます。
  • 直している間は、直した所を撮って見せるだけです。検査は公開の前に1回。急ぎのときは、責任者の指示で急ぎの公開（8章）にできます。
  • 比較画像は1枚：スマホの幅の1サイズで、直した所を「修正前｜修正後」で切り出し、全部を1枚に縦に積みます（多いときだけ道具が2枚に分けます）。PC でしか見えない直しのときだけ、PC の1サイズにします。画像は公開したあとの URL 同士で作ります。
  • 渡す順番は「返信文の下書き → すぐ画像」。送るのはあなたです。
  • 先方の文言は、Slack・シートの原文から写します（転送文・要約から写しません）。

10WordPress への移行（WP化）

HP 版の WP化の手順は、まだありません（未整備）。WP化の段になったら、進め方を責任者に確認してください。AI は認証情報（FTP・WordPress の ID とパスワード）を扱いません。

先にできること：CSS の散らかりを0件にしておく（見た目を変えない整理だけ）。

11困ったとき

検査で止まった

✕ の行に、ページ・画面の大きさ・理由が出ます。AI に「✕ を直して、同じコマンドを流し直して」と伝えます。検査を通すために、除外の指定で消すことはしません。

公開で止まった

「承認の行がありません」は、その版の責任者の OK がまだ記録されていない、という意味です。「もう公開しています」は、同じ版へ出し直そうとしたときです（次の番号で出します）。

キットがおかしい

tools/version.sh で、キットの版と、キット本体が書き換わっていないかが分かります。不具合・足りない所は、AI に直させず、責任者へ伝えてください。

12守ること

  1. 顧客の情報を外に出さない

    ヒアリングシート・写真・ロゴ・参考サイトの複製を、キットの外やほかの案件へ持ち出しません。認証情報は AI に読ませません。

  2. 公開と送信は人が承認する

    公開・クライアントへの送信・Slack への投稿は、あなたと責任者が決めます。AI は下書きまでです。

  3. 「OK」は人が出す

    承認の記録は、責任者がはっきり OK を伝えたときだけ書かれます。AI の判断では書きません。

  4. 事実を足さない

    シートに無い電話・住所・数字・実績を、AI に作らせません。先方の文言は言い換えません。

  5. キットを書き換えない・再配布しない

    手順書・道具・土台は直しません。キットと、このページのダウンロードのリンクを、ほかの人に渡しません。
