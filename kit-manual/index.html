採用LP 制作キットの使い方

このキットを初めて使う制作者の方のための手引きです。AI やターミナル（文字でパソコンに指示を出す画面）に慣れていなくても進められるよう、「あなたがすること」と「AI がすること」を分けて書いています。

1このページについて

結論：キットを Mac に置き、AI（Claude Code または Codex）でキットのフォルダを開いて「手順0から始めて」と伝えれば、AI が作業ルールに沿って採用LPを作ります。品質は検査の道具が止めるので、あなたの仕事は「選ぶ・見る・承認する・送る」が中心です。

できること

  • ヒアリングシートから、縦スワイプ型（1回の操作で1ページ進む形）の採用LPを作る
  • 文言・収まり・重なり・配色・ページ送りを道具で検査する
  • 合格したものだけを、あなたの Cloudflare で公開する

初稿までの目安

33〜72分

弊社の担当が作った5本の実測（確認待ちの時間を除く）。初めての方は、これより長くかかる見込みです（ほかの制作者での実測はまだありません）。全ページの検査は1回あたり約7分です。

このキットの版

v2.6

2026年10月21日。版は ZIP の名前と、キットの中の CHANGELOG.md（更新の履歴）で分かります。

4初回だけの準備

結論：5つの手順で、ソフトの点検がすべて OK になり、AI でキットのフォルダを開けたら準備は終わりです。30分〜1時間ほどを見てください（ソフトの入れ方で変わります。目安で、実測ではありません）。

ターミナルの開き方：Finder →「アプリケーション」→「ユーティリティ」→「ターミナル」。下の黒い枠のコマンドは、右上の「コピー」で写し、ターミナルに貼り付けて Return キーを押します。

  1. ZIP を置く場所を決めて、解凍する

    例：ホームの「書類（Documents）」の中に「LP制作」フォルダを作り、その中で ZIP を解凍します。spinova-lp-kit というフォルダができます。

    避ける場所：iCloud Drive・Google Drive・Dropbox など、自動で同期されるフォルダの中。顧客のシートや写真が外へ同期されてしまうためです（同期で検査も遅くなります）。

  2. ソフトを入れる（公式の入れ方）

    すでに入っているものは飛ばして構いません。次の手順3の点検で、足りないものが分かります。

    • Google Chrome：https://www.google.com/chrome/ からダウンロードし、「アプリケーション」に入れる
    • Node.js：https://nodejs.org/ から「LTS（推奨版）」のインストーラを入れる（npx も入ります）
    • git と Python 3：Apple の開発用ツールに入っています。ターミナルで次を実行し、出てきた画面で「インストール」を押します。 
      xcode-select --install

      「すでにインストールされています」と出たら、そのままで大丈夫です。Python は python.org のインストーラでも入れられます。

    • openpyxl と Pillow（Python の追加の部品）： 
      python3 -m pip install --user openpyxl Pillow
    • ffmpeg：Homebrew（Mac にソフトを入れる道具。https://brew.sh/）を使います。Homebrew が無ければ、公式ページのコマンドで先に入れます。 
      /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

      終わりに表示される「Next steps」の2行（PATH の設定）も、表示どおりに実行してください。そのあとで：

      brew install ffmpeg
    • AI（どちらか1つ）：入れ方は変わることがあるので、各社の公式の案内も確かめてください。 
      # Claude Code（Anthropic）
npm install -g @anthropic-ai/claude-code
      # Codex（OpenAI）
npm install -g @openai/codex

      初めて起動したときに、それぞれのアカウントでのログインを求められます。ログインはあなたが行います。

  3. 点検する（setup_check.sh）

    キットのフォルダに移動して、点検の道具を動かします。要るソフトの有無と版が表で出ます。入れる操作はしません（足りないものは入れ方が1行で出ます）。

    cd ~/Documents/LP制作/spinova-lp-kit
tools/setup_check.sh

    1行目はキットを置いた場所に合わせて直します（Finder でフォルダをターミナルへドラッグすると場所が入ります）。最後に「判定：必要なものはそろっています」と出れば次へ。Safari の行は任意で、状態だけを出します。

    Safari の検査も使うなら（任意・1回だけ）：sudo safaridriver --enable（Mac のパスワードを聞かれます。入れるのはあなた）→ Safari の「開発」メニュー →「リモートオートメーションを許可」。「開発」メニューが無ければ、Safari の設定 →「詳細」→「Web デベロッパ用の機能を表示」。

  4. Cloudflare にログインする

    公開に使う wrangler（Cloudflare へ送る道具）を、あなたのアカウントにつなぎます。ブラウザが開くので、あなたがログインして許可します。

    npx wrangler login

    公開は必ずキットの tools/publish.sh で行います。wrangler を直接使って公開しないでください（検査を飛ばしてしまうため）。

  5. AI でキットのフォルダを開く

    ターミナルでキットのフォルダに移動してから、AI を起動します。AI は作業ルール（Claude Code は CLAUDE.md、Codex は AGENTS.md。中身は同じ）を自動で読みます。

    cd ~/Documents/LP制作/spinova-lp-kit
claude        # Claude Code の場合
# codex       # Codex の場合はこちら

    AI がファイルの編集やコマンドの実行の許可を求めてきたら、内容を見て許可します。公開と外への送信は、毎回あなたが承認してください。

5案件ごとの手順：初稿を出すまで

結論：Slack に来た担当案件の URL を AI に貼り、「手順0から始めて」と伝えます。あとは AI が手順0〜8.8を進め、あなたは選ぶ・見る・承認する・送るを受け持ちます。

AI への最初の一言（例）

作業ルール（AGENTS.md／CLAUDE.md）を読んで、新しい案件を手順0から始めてください。
担当案件：〔Slack の担当案件の URL を貼る〕
進め方の選択・公開・先方への送信・最終チェックの承認欄は、私が決めます。

以下の各手順は、あなたがすること AI がすること 確かめること・つまずきやすい点 の3つに分けています。「手順」の番号はキットの作業ルール（2章）と同じです。

0進め方を選ぶ（最初に必ず）
あなたがすること
  • AI が出す3つの問いに、選択肢から答える：①最初の数ページで一度確認するか ②初稿を全ページで出すか、最初の数ページだけか ③初稿の案を3案にするか、1案か
AI がすること
  • 3つを選択式で聞く（AI は決めない）
  • 選んだ内容と日付を 要件整理.md に書く
確かめること
  • AI が問いを飛ばして勝手に決めていないか（過去に3案を飛ばした例あり）
1案件を作る
あなたがすること
  • なし（「最初の一言」で貼った Slack の URL を、AI がそのまま使います）
AI がすること
  • シート・素材を取り込み、tools/new_project.sh で projects/<案件名>/ を作る（土台とひな形が複製される）
つまずきやすい点
  • AI が Slack を読めない設定のときは、シートと素材をあなたがダウンロードし、置いた場所を AI に伝える（Slack から取り込む専用の道具はまだありません）
2シートを書き出す
あなたがすること
  • 特になし
AI がすること
  • tools/dump_sheet.py でヒアリングシートを文字に書き出す
  • kit.conf（案件の設定のファイル）の原稿の場所と照合するセクションをシートに合わせる
確かめること
  • 見出しの無い列（欄外のメモ）まで書き出されているか
3要件整理（シートの照合表）
あなたがすること
  • AI が「未定」として出した点を、選択肢から決める
  • 開かれたシートと参考サイトのタブを見ておく
AI がすること
  • 要件整理.md を確定／解釈／未定に分けて埋める
  • シートの全セル・全補足を1行ずつ抜き出した照合表（✓△✕）を作る
  • シートと参考サイトをブラウザのタブで開く
確かめること
  • 照合表に ✕ が残っていないか（配色の役割・雰囲気の文の読み落としが多い）
  • シートに「スクロール形式」「画像で」などの指定があれば、それが最優先
4参考サイトの分析（最も大事な工程）
あなたがすること
  • AI が書いた「この参考サイトらしさ」（5つ以上）と、ページごとの割り当て表を読む
AI がすること
  • tools/refcap.mjs で参考サイトの動きをスマホ幅と PC 幅で記録し、コマを全部見る
  • 数値・型・時間割だけを DNA.md に書く（コード・画像は持ち込まない）
  • 参考の全セクションの型の表と、自分のページへの割り当て表を作る
つまずきやすい点
  • 参考サイトに何度もアクセスすると、相手にブロックされることがある（8章）
  • 割り当て表が空のまま実装に進んでいないか
5土台に流し込む
あなたがすること
  • 特になし
AI がすること
  • DNA の値を site/tokens.css に、見た目を site/style.css に書く
  • 型の部品集（templates/parts/）から合うものを使う
確かめること
  • 土台（base.css・swipe.js）を書き換えていないか。書き換えると記録の ZIP に「✕」と出る
6初稿（1案または3案）
あなたがすること
  • 3案のときは、ページごとの比較動画を見て案を選ぶ
AI がすること
  • 型は参考に忠実、中身（モチーフ・小物）は案件の業種に置き換える。各ページに「遊び」を1つ
  • 3案のときは tools/new_draft.sh で案を分け、tools/preview.mjs で比較動画を作る
確かめること
  • 写真・イラストの人物が日本人か、指の形が崩れていないか（原寸で見る）
6.5参考との並べ比べ
あなたがすること
  • 参考と自作を同じ時刻で並べた画像を見る
AI がすること
  • 自作も同じ道具で記録し、tools/compare.sh で上下に並べる。結果を DNA.md に書く
確かめること
  • 出る順番・速さ・明るさ・質感・余白が参考に近いか
6.8OGP 画像（必須）
あなたがすること
  • できた画像を見る
AI がすること
  • tools/make_ogp.py で 1200×630 の画像を作り、HTML の og:url・og:image を公開先の URL にする
確かめること
  • URL が仮のままだと検査で不合格になる
7検査（すべて合格まで）
あなたがすること
  • 最後に「判定：すべて合格」と出たかを見る
AI がすること
  • tools/run_all.sh projects/<案件名> で検査し、✕ を直して合格まで繰り返す
  • 作業中は --quick（2サイズだけ）で確かめる
つまずきやすい点
  • 全ページの検査は1回あたり約7分。小さな直しのたびに全部を回さない
  • 「Safari 未検査」は不合格ではないが、未確認として残る
7.5あなたが確かめて、直してほしい所を AI に伝える（いちばん大事）
あなたがすること
  • AI が出した一覧画像と画面を、携帯と PC の両方で見る
  • 10原則（6章）に当てて、気になる所を探す
  • 直してほしい所を、まとめて1回でチャットに書く（下の例文）
  • 直った画面を見て、まだあれば同じようにもう1回。無ければ「OK」
AI がすること
  • 検査に合格したら、一覧画像（全ページ・3サイズ）と、画面を開く URL を渡す
  • 伝えられた所を全部まとめて直し、直したページだけ検査する
  • 直す前と後を並べて見せる
伝え方のコツ
  • 「何ページ目の・どこを・どうしたいか」を1件ずつ書く
  • 見た目の話はスクリーンショットを添えると早い
  • 思いついたたびに1件ずつ送らない。まとめて送るほど早く終わる
直してほしい所です。まとめて直して、直したページだけ検査してから、前と後を見せてください。
1. 3ページ目：見出しと写真が近すぎる。間をもう少し空けたい
2. 5ページ目：スマホで「〇〇」が途中で改行される。1行にしたい
3. 全体：ボタンの色が薄い。もう少し濃く
8提出の前（10原則・一覧画像）
あなたがすること
  • 7.5 で直しきったら、最後に一覧画像をひととおり見る
AI がすること
  • 提出チェック.md を埋め、10原則を全項目回す
  • 全ページの一覧画像（360×640・390×844・1440×900）を作り直す
確かめること
  • 検査がすべて合格していること（AI が報告する）
8.5公開（チャットで「OK」と言うだけ）
あなたがすること
  • チャットで 「OK、公開に進んで」 と言うだけ
  • 公開のあとに出る記録の ZIP を、Slack の SPINOVA との共有の場所に貼る
AI がすること
  • あなたの「OK」を受けて、承認欄を代わりに書く（tools/approve.sh。名前と今日の日付が入る）
  • tools/publish.sh で版の URL（https://v1.<名前>.pages.dev/）に公開し、公開側と照合する
  • 公開に成功すると、作業記録が自動で ZIP にまとまる
確かめること
  • 「OK」と言わない限り、AI は承認欄を書かず、公開もしない
  • 名前は初回に一度 AI に伝える（キットの案件の設定 kit.conf の APPROVER に入る）
8.8共有文面
あなたがすること
  • 文面を確かめて、ディレクターへ送る（送るのはあなた）
AI がすること
  • 共有文面.md の型で、URL と「シートの指定に合わせて通常と変えた点」だけの短い文を作る
確かめること
  • 経緯・前置きを足して長くしない

先方の確認が済んだあとの WordPress 化（手順9.8）は、先方のマニュアルの工程どおりに進めます。WordPress へのログインと管理画面の操作は人が行います。

6提出前のチェック：全案件に共通の10原則

結論：提出の前に、AI がこの10原則を全項目回し、あなた（責任者）が一覧画像で確かめて承認します。中身はキットの templates/先方指摘チェックリスト.md にあります。

確かめる段は3つ（A・B・C）

A道具が判定

道具が合否を出し、AI が直す。人は見なくてよい。不合格なら公開できない。

BAI が見て、人が承認

AI が見て直し、責任者が一覧画像で承認する。AI の「OK」だけで出さない（AI の目は100%ではない）。

C人だけが判断

見た目の質・参考らしさ・写真の選び方・実機の触り心地・提出の判断。AI は案を出すだけ。

#原則段道具で止めるもの（A）目で確かめるもの（B・C）
デザイン
1参考サイトのテイストに寄せる（型は参考に忠実、中身は案件に置き換え）B・C－並べ比べを一覧画像に入れて見る
2余白は詰めすぎず、均等にA＋B上下の余白・縦の詰まり要素の間（間隔は3段階）・項目名と値の縦の線
3文字を被せない・はみ出させない・背景と十分な差A重なり・コントラスト（本文 4.5:1・大きい文字 3:1）・はみ出し・Safari疑似要素で描いた絵・タブで隠れた側・動画の別のコマ
4文字は小さすぎず、意味のまとまりで折るA＋B最小 13px（全サイズ）文節の途中の折れ（iPhone の幅で）・強調の句が1行か
5同じ役割はそろえ、最後まで続けるA⚠＋B簡素なページ（⚠）・語の重複（⚠）札・見出しの体裁・後半まで背景のあしらいが続くか
6画像を破綻させない（人物は日本人・指や形・装飾は指定どおり）B・C－指の数・形を原寸で・矢印や線の形・吹き出しの塗り
7動きは速く（動き出し 0.3秒以内・1ページ 2秒以内に出そろう）B－出る順番と速さ
実装
8型と操作が PC・スマホで動くA＋Cシートの形式・ヘッダーの移動・ページ送り横に並んだ部品の送り・iPhone 実機の触り心地
9文言とシートを守る（一言一句）A＋B文言照合・シートの書き出し照合表 ✓△✕・文言の変更依頼の記録
10公開の形をそろえる（版ごとの URL・OGP・1枚目の仮動画）A構成の検査・版ごとの公開－

提出の前の流れ

  1. 道具（A）がすべて合格する（run_all.sh の「判定：すべて合格」）
  2. AI が一覧画像を作り、10原則に1つずつ当てて全ページを見る
  3. 責任者が一覧画像と画面（携帯・PC）を見て、チャットで「OK、公開に進んで」と伝える → AI が承認欄（承認者・日付）を代わりに書く
  4. 公開 → 共有文面で提出

7修正が来たら

結論：修正はまとめて直し、版を上げて（v1 → v2）出し直します。検査は直したセクションだけを道具が選んで回します。

  1. 修正をまとめて AI に渡す

    先方の指摘（スクリーンショットがあれば一緒に）をまとめて渡します。AI は直す場所を添付画像で確かめてから直します。

    先方から修正が来ました。下の指摘をまとめて直し、版を v2 にして出せる状態にしてください。
〔指摘を貼る〕

  2. 直している途中は、直したページだけ確かめる

    AI は tools/run_all.sh … --quick や --pages=3,5（直したページだけ）で確かめます。小さな直しのたびに全ページの検査を回しません。

  3. 版を上げて公開する

    tools/publish.sh projects/<案件名> --version v2。道具が、初稿の合格のときに作った基準（比べるための記録）と比べ、直したセクションだけを検査します。共有の CSS を直したときは、全ページの画面を基準と比べ、崩れたページも検査に入れます。迷うとき・大きく作り直したときは --full（全ページ）。

    前の版の URL は上書きしません（先方が持っている URL を残すため）。公開の前に、承認欄を一覧画像で見直して書き直します。

  4. 記録を残して送る

    公開に成功すると、作業記録の ZIP が自動でできます（理由は「修正（v2）」）。Slack の SPINOVA との共有の場所に貼ります。区切りごとに 修正記録_<案件>_<日付>.md（指摘・原因・直し方）も AI が残します。

新しい指摘は、10原則のどれに当たるかを決めて記録します（項目を増やさない）。

8困ったとき・記録の送り方

結論：困ったら、AI に「作業記録をまとめて」と言い、できた ZIP を Slack の SPINOVA との共有の場所に貼って、何が起きたかを一言添えてください。弊社が同じ案件を弊社の Mac で動かし、あなたの Mac の問題か、キットの問題かを切り分けます。

記録の ZIP

いつできるか

  • 自動：公開に成功するたび（初稿＝「初稿（v1）」、修正版＝「修正（vN）」）
  • 手で：完了のとき・困ったとき（下の一言を AI に）
作業記録をまとめてください。理由は「困ったとき：〔何が起きたか〕」です。

AI は tools/report_pack.sh projects/<案件名> --reason "困ったとき：…" を実行します。完了のときは --reason "完了"。

中身

  • 入るもの（文章だけ）：キットの版・最終チェック・公開の記録・作業記録・修正記録・要件整理と DNA・検査の出力・あなたの Mac の環境（macOS・Chrome・Node などの版・機種名・トラックパッドとマウスの設定）・土台が書き換えられていないかの判定
  • 入らないもの：顧客の写真・ロゴ・動画・ヒアリングシート・素材・参考サイトの複製
  • トークン・パスワードに見える値は伏せられます

場所：projects/<案件名>/_report/記録_<日時>_<理由>.zip。送るのはあなたです（道具も AI も送りません）。

よくある問題と対処

スクロール（ページ送り）がおかしい
  • まず run_all.sh の「ページ送り」が合格かを見ます。合格なら道具の上では正しく動いています
  • AI のアプリの中のブラウザで動きを見ない。画面が裏に回ると動きが止まって見えます。Chrome かスマホで見ます
  • 土台の swipe.js・base.css を直して解決しようとしない（キットの問題として記録の ZIP で知らせる）
  • iPhone の実機の触り心地は道具では測れません（C の承認で人が触る）
検査が通らない（✕ が消えない）
  • ✕ の行に、ページ・画面サイズ・要素が出ます。AI に「上の ✕ を直して」と頼みます
  • 道具の判定を外す設定（--ignore）で消さない。写真の上の文字は文字の後ろに地を敷いて data-on-photo、意図してはみ出させる絵は data-bleed を付けます
  • 何度直しても通らないときは、AI に「作業記録をまとめて」と言い、ZIP を Slack に貼ります
「Safari 未検査」と出る
  • 不合格ではありません。Safari の自動操作が有効になっていないだけです
  • 有効にする（1回だけ）：ターミナルで sudo safaridriver --enable → Safari の「開発」メニュー →「リモートオートメーションを許可」
  • 有効にしないまま出すときは、提出チェック.md に「未確認」と書きます
参考サイトにアクセスできない・ブロックされた
  • 参考サイトの記録で多くのファイルを一度に取ると、相手に IP をブロックされることがあります（過去に1件）
  • 記録は PC 幅 → スマホ幅の順に撮り、2回目以降は --no-assets を付けます
  • ブロックされたら、何度もアクセスし直さない。すでに開いているブラウザのタブと、撮れた画面から読み取ります
確認用の簡易サーバーが起動しない
  • python3 -m http.server が起動しない環境があります。その場合は Node の簡易サーバーを使います（AI に「node の簡易サーバーで開いて」と頼む）
スマホで古い動画・画像が出る
  • 読み込みに ?v=（版の印）が付いていないと、スマホが古いものを覚えたまま表示します。検査の「構成」で付け忘れを見ています。公開のたびに上げます
公開で止まる（承認・ログイン）
  • 「最終チェック.md の承認がそろっていません」：まだ「OK」を伝えていない。画面を確かめて、チャットで「OK、公開に進んで」と伝える
  • 「プロジェクト一覧を取得できません」：npx wrangler login でログインし直す
  • 公開側の照合で「反映待ち」が続く：反映に数十秒かかることがあります。道具が自動で待ち直します
キットにまだ無いもの
  • Slack から案件の資料を取り込む専用の道具：まだありません（AI が読めないときは、あなたがダウンロードします）
  • Windows での動作：まだ確かめていません
  • 作業ルールの要点版（最初に読む量を減らしたもの）：まだありません

9守ること

次の5つは必ず守ってください。品質と、顧客・御社・弊社の信用を守るための決まりです。

  1. 顧客の情報を外に出さない

    ヒアリングシート・写真・ロゴ・参考サイトの複製を、キットの外や他のサービスに出さない。公開するのは site/ の中だけです（道具がそれ以外を入れません）。参考サイトの複製は _analysis/ の中だけで扱います。

  2. 公開と送信は人が承認する

    公開（--dry-run を付けない実行）・先方への送信・Slack への投稿は、毎回あなたが確かめて行います。AI に送らせない。

  3. 「OK」はあなたが出す

    承認欄（最終チェック.md の「承認者：」「日付：」）は、あなたがチャットで「OK、公開に進んで」とはっきり伝えたときだけ、AI が代わりに書きます。画面を見ないまま「OK」を出さないでください。AI が自分の判断で承認欄を書くことはありません。

  4. キットの土台を書き換えない

    base.css・swipe.js（土台）と tools/（道具）は直さない。案件だけの動きは site/site.js に書きます。土台に問題があれば、記録の ZIP で弊社に知らせてください。

  5. キットを再配布しない

    キットと、このページのダウンロードのリンクを、ほかの人・ほかの会社に渡さない。キットの道具は弊社（HSE）の所有です。
